# 兵种分类与技能树规划

## 当前实现范围

当前目录固定为 9 个兵种：3 个大类，每个大类 3 个小类。兵种分类使用两个正式字段：

- `unitCategory`：`melee`、`ranged`、`support`
- `unitSubtype`：近战/远程使用 `mobility`、`defense`、`balance`；辅助使用 `combination`、`comprehensive`、`intervention`

`rpsType` 目前与 `unitCategory` 保持一致，仅用于兼容已有的三角克制计算，不代表技能树。当前克制顺序为：近战克制远程，远程克制辅助，辅助克制近战。

技能不属于兵种数据。兵种目录不再保存 `abilityIds`，`UnitComponent` 的 `ability` 类型仅为后续独立技能目录预留。

## 技能树面板与后续配置

兵营现在提供“技能树”选项卡，三棵技能树严格对应近战、远程、辅助三个大类，不绑定某一个具体兵种。当前面板仅用于展示节点、前置连线、分支路线和技能详情，不包含技能点、升级、学习、重置或本地进度。

### 部队技能树槽位

- 每支部队最多配置 3 个技能槽位，每个槽位选择一个大类技能树和该树中的一个技能。
- 槽位允许重复大类，但只能选择部队中已经存在的大类兵种。
- 例如部队含近战和辅助时，可以选择两个近战技能树和一个辅助技能树，不能选择远程技能树。
- 同一技能被多个槽位重复选择时，首个槽位正常显示，后续槽位显示 `Ban` 冲突占位；冲突槽位仍然有效，可以继续更换技能。
- 技能树槽位属于训练场实际部署部队，不属于部队模板或 `ArmyUnitType`。运行时冷却保存在实际部署部队槽位中。

### 三大类技能树方向

#### 近战技能树

- 统一服务近战大类部队，重点表现集体重击、快速斩击、巡回步、武器气、气浪、气刃和周驰。
- 近战兵种的小类只影响部队的机动、防御或平衡属性，不产生独立技能树。

#### 远程技能树

- 统一服务远程大类部队，重点表现定点齐射、急行射击、穿透弹幕、远程狙杀、区域压制和弹道强化。
- 远程兵种的小类只影响部队的机动、防御或平衡属性，不产生独立技能树。

#### 辅助技能树

- 统一服务辅助大类部队，重点表现组合强化、全面调律、净化脉冲、战场共鸣和干预领域。
- 辅助兵种的小类决定增益偏向：组合型集中强化部分属性，全面型覆盖综合属性，干预型负责解控、净化和敌方减益。

### 分支形状

每棵技能树使用 4 层结构，从上至下逐步展开：

```text
顶层：1 个核心节点
第二层：2 个方向节点
第三层：3 个专精分支
底层：3 个终式节点
```

这样可以让技能树从一个共同核心逐步分流到三个明确的战术终点，满足“最下面最多三个分支、越往上越少”的结构要求。

### 技能与施放规则

- 每支部队最多选择 3 个具体技能，技能可以来自同一大类技能树，也可以重复选择同一大类但不能重复具体技能。
- 技能拥有自己的 `cooldownSec`、目标范围、效果和持续时间，CD 不由兵种决定。
- 技能保存大类 `treeCategory`，而不是保存具体 `unitTypeId`。
- 对战时由部队中对应大类的士兵贡献施放能力；部队没有该大类兵种时，技能不能生效。
- 技能树面板负责展示路线，训练营技能槽负责选择具体技能，战斗施放负责决定“由谁施放”，三者保持独立。

训练营实际部队使用以下结构保存技能选择，冷却剩余时间只存在运行时：

```json
{
  "skillSlots": [
    { "slotIndex": 0, "treeCategory": "melee", "skillId": "melee_heavy_blow" },
    { "slotIndex": 1, "treeCategory": "melee", "skillId": "melee_circular_step" },
    { "slotIndex": 2, "treeCategory": "support", "skillId": "support_purification_pulse" }
  ]
}
```
